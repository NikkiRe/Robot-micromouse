# Прошивка v2

Вторая версия прошивки робота Micromouse: STM32F401CCU6 (Black Pill),
драйвер TB6612FNG, два мотора N20 без энкодеров, три цифровых ИК-датчика
YL-63. В отличие от базовой прошивки (`../Core/Src/main.c`) строит карту
стен, считает путь заливкой (flood-fill) и едет по схеме исследование →
возврат → скоростной заезд.

Энкодеров и датчиков расстояния нет, поэтому проезд клетки и повороты
делаются по таймеру (открытый цикл).

## Состав

```
firmware-v2/
├── Core/Inc/
│   ├── main.h      распиновка, LED, кнопка
│   ├── motors.h    TB6612FNG + ШИМ TIM1, выравнивание моторов
│   ├── sensors.h   ИК-датчики, медианный фильтр
│   ├── maze.h      карта 16×16, flood-fill (без HAL)
│   ├── nav.h       машина состояний, тайминги
│   └── calib.h     режим калибровки
├── Core/Src/       реализации + main.c
├── host-test/
│   ├── test_maze.c тесты карты и заливки, симуляция заезда
│   └── Makefile    make test
├── PINOUT.md       распиновка и правки в CubeMX
└── README.md
```

Зависимости: `main → calib → nav → maze`, `nav → motors, sensors → HAL`.
`maze` — чистый C, компилируется на хосте.

## Как работает

Карта (`maze.c`): поле 16×16, `x` на восток, `y` на север, старт `(0,0)`,
робот носом на север, центр — клетки `(7..8, 7..8)`. Клетка — байт: биты стен
N/E/S/W и бит «осмотрена». Периметр известен заранее, стена пишется с двух
сторон. `maze_flood()` — BFS на статической очереди, два режима:
оптимистичный (неизвестные стены нет) для исследования и `known_only` (только
осмотренные клетки) для скоростного заезда. `maze_best_dir()` берёт соседа
с меньшим расстоянием, при равенстве прямо → налево → направо → назад.

Цикл клетки (`nav.c`): стоим в середине клетки, читаем датчики (медиана из
5), пишем стены в карту, заливка, выбор направления, поворот на месте по
таймеру, проезд клетки по таймеру. Во второй половине проезда опрашивается
центральный датчик (`NAV_FRONT_STOP`): стена перед носом — стоп раньше
таймера. Остановка — короткое торможение и пауза `NAV_SETTLE_MS`.

ШИМ: TIM1 20 кГц, CH1 → PA8 (PWMA, правый), CH3 → PA10 (PWMB, левый).
Подробности в `PINOUT.md`.

Состояния:

| Состояние | Что делает | LED PC13 |
|---|---|---|
| ожидание старта | ждём кнопку | мигает 1 Гц |
| `EXPLORE` | к центру, карта заполняется | погашен |
| `RETURN` | к старту, карта дописывается | вспышка на клетке |
| `WAIT_RUN` | стоим на старте, ждём кнопку | мигает 2 Гц |
| `SPEED_RUN` | к центру по осмотренным клеткам | горит |
| `DONE` | финиш, кнопка → ещё заезд | 3 вспышки, пауза |
| `ERROR` | пути нет или лимит `NAV_MAX_STEPS`, драйвер выключен | частое мигание |

В `WAIT_RUN` робота нужно руками поставить в стартовую клетку носом на
север: поза сбрасывается в `(0,0,N)`, накопленная за исследование ошибка
обнуляется.

## Сборка

Хост-тесты:

```
cd firmware-v2/host-test
make test
```

Нужен любой `cc`. `maze.c` собирается с `-Wconversion -Werror` и
sanitizer'ами. Ожидаемый вывод: `955 проверок, 0 ошибок — OK`.

Прошивка (STM32CubeIDE):

1. Внести правки в `robot.ioc` по `PINOUT.md`, нажать Generate Code.
2. Добавить в проект `firmware-v2/Core/Src/*.c` и `firmware-v2/Core/Inc/*.h`,
   базовый `Core/Src/main.c` из сборки исключить. Остальные файлы CubeMX
   (`stm32f4xx_it.c`, `stm32f4xx_hal_msp.c`, `system_stm32f4xx.c`,
   `syscalls.c`, `sysmem.c`, стартап, `Drivers/`) без изменений.
3. `Project → Build Project`, при необходимости
   `arm-none-eabi-objcopy -O binary robot.elf robot.bin`.

Из командной строки: `arm-none-eabi-gcc -mcpu=cortex-m4 -mthumb
-mfpu=fpv4-sp-d16 -mfloat-abi=hard -DUSE_HAL_DRIVER -DSTM32F401xC`, пути к
`Core/Inc`, `Drivers/STM32F4xx_HAL_Driver/Inc`, `Drivers/CMSIS/...`, линковка
с `STM32F401CCUX_FLASH.ld`, `--specs=nano.specs --specs=nosys.specs`.
Около 8 КБ flash и 2.5 КБ ОЗУ.

Если PWMB ещё не заведён на PA10: `-DMOTORS_PWMB_ON_PA10=0`.

## Прошивка через DFU

1. Подключить плату по USB.
2. Зажать BOOT0, нажать и отпустить NRST, отпустить BOOT0.
3. `dfu-util -a 0 -s 0x08000000:leave -D robot.bin` (или STM32CubeProgrammer).
4. Плата перезапускается, LED дважды мигает.

PA11/PA12 не используются, загрузчик остаётся доступен.

## Запуск

1. Подать питание: LED дважды мигнёт, потом мигает 1 Гц.
2. Поставить робота в `(0,0)` носом на «север».
3. Нажать KEY, через 2 с робот поедет (LED погашен).
4. В центре три вспышки, робот возвращается.
5. На старте LED мигает 2 Гц: выровнять робота, нажать KEY — скоростной заезд.
6. В центре три вспышки. Кнопка → ещё заезд (робота снова на старт).

## Калибровка

Тайминги в `nav.h` и `motors.h` — заготовки, под конкретного робота их надо
подобрать.

| Константа | Файл | Смысл |
|---|---|---|
| `NAV_SPEED_PCT` | `nav.h` | заполнение ШИМ, тайминги действительны только для него |
| `FORWARD_CELL_MS` | `nav.h` | проезд одной клетки (180 мм) |
| `TURN90_MS` | `nav.h` | поворот на 90° |
| `TURN180_MS` | `nav.h` | разворот, отдельно от `2×TURN90` |
| `NAV_SETTLE_MS` | `nav.h` | пауза после торможения |
| `MOTOR_TRIM_LEFT/RIGHT` | `motors.h` | выравнивание моторов, % |
| `SENSOR_SAMPLES` | `sensors.h` | глубина медианы |

Режим калибровки: удерживать KEY при подаче питания (LED горит). После
отпускания и паузы 2 с робот делает:

1. четыре поворота направо на 90° — должен смотреть туда же, куда в начале;
   недокрут → увеличить `TURN90_MS`, перекрут → уменьшить;
2. проезд пяти клеток с остановками — должен встать в середине шестой;
   недоехал/переехал → `FORWARD_CELL_MS`; уводит влево → уменьшить
   `MOTOR_TRIM_RIGHT`, вправо → `MOTOR_TRIM_LEFT`;
3. два разворота на 180° → `TURN180_MS`.

Потом LED мигает, кнопка повторяет сценарий. Порядок: сначала
`MOTOR_TRIM_*`, потом `FORWARD_CELL_MS`, потом повороты. Калибровать на том
же покрытии и заряде батареи, что на соревновании.

Пороги датчиков — подстроечниками на YL-63: боковые видят стену из середины
клетки, но не через проход; центральный видит стену с ~9 см и не видит
с ~27 см.

## Что изменилось относительно базовой прошивки

| Было | Стало |
|---|---|
| Один `main.c`, вся логика в `while(1)` | Модули `motors / sensors / maze / nav / calib` |
| Реактивно: «спереди стена → поворот» | Карта стен, flood-fill, маршрут к центру и обратно, скоростной заезд |
| Нет памяти о пройденном | Карта 16×16, бит «осмотрено», `NAV_MAX_STEPS`, состояние `ERROR` |
| Soft-PWM 40 мс / 20 мс | Аппаратный ШИМ TIM1 20 кГц, заполнение на каждый мотор, `MOTOR_TRIM_*` |
| PWMA на PA8 постоянно HIGH, PWMB не подключён | PWMA = TIM1_CH1 (PA8), PWMB = TIM1_CH3 (PA10), один новый провод |
| PA9 в `.ioc` под TIM1_CH2 (конфликт со STBY) | PA9 — GPIO STBY, `HAL_TIM_MspPostInit` не используется |
| Датчики одним чтением | Медиана из 5 выборок |
| Старт сразу при подаче питания | Кнопка KEY (PA0), пауза 2 с; кнопка при включении → калибровка |
| Тайминги внутри `HAL_Delay` | Константы в `nav.h`, режим калибровки |
| Остановка выбегом | Короткое торможение + пауза до чтения датчиков |
| Тестов нет | `host-test/`, 955 проверок |

Не изменилось: HSI 16 МГц без PLL, HAL, DFU, распиновка моторов и датчиков,
линкер-скрипт.

## Ограничения

Открытый цикл: ошибка копится с каждым манёвром и зависит от батареи и
покрытия, на длинных маршрутах робот сползает с сетки. Моторы неодинаковы,
`MOTOR_TRIM_*` выравнивает их только в одной рабочей точке. Датчики бинарные,
ложная стена в карте не стирается и может привести к `ERROR`. Диагонали,
плавные повороты и ускорение не реализованы.
